## 3. Общие правила

- Время сравнивается с временем старта слота, полученным от Client API, а не с локальным устройством.
- Существующий бэкенд является источником истины по местам, статусам и конкурентным операциям.
- В каждом сценарии явно указаны предусловия, успешный поток, альтернативные потоки и потоки исключений.
- Для обязательных проверок используются единые классы ошибок: ошибка SMS, конкурентная нехватка мест и отмена после дедлайна. Если класс не применим к конкретному use case, это указано явно.

## 4. UC-001 — Вход по номеру телефона и SMS

### Предусловия

- Приложение установлено и запущено.
- У клиента есть номер телефона в формате `+7XXXXXXXXXX`.
- Клиент ещё не авторизован.

### Основной успешный поток

1. Приложение открывает экран входа.
2. Клиент вводит номер телефона.
3. Приложение проверяет формат номера.
4. Приложение вызывает `API-AUTH-001` для отправки SMS-кода.
5. Клиент вводит полученный код.
6. Приложение вызывает `API-AUTH-002` для проверки кода.
7. Client API возвращает действующую клиентскую сессию.
8. Приложение открывает расписание.

### Альтернативные потоки

- **ALT-001-A:** клиент хочет изменить номер телефона и возвращается к полю ввода.
- **ALT-001-B:** код не пришёл, клиент повторно запрашивает его после доступного времени ожидания.
- **ALT-001-C:** клиент отказывается от входа и закрывает приложение без создания записи.

### Потоки исключений

| ID | Событие | Реакция приложения | Восстановление |
|---|---|---|---|
| EXC-001-01 | Ошибка отправки SMS или сети | Сессия не создаётся, показывается сообщение о недоступности | Клиент повторяет запрос после подключения |
| EXC-001-02 | Неверный или истёкший код | Показать ошибку, оставить возможность ввести новый код | Запросить новый SMS-код |
| EXC-001-03 | 0 свободных мест при запросе | Не применимо: вход не создаёт бронь и не проверяет слот | Перейти к UC-002 после авторизации |
| EXC-001-04 | Отмена после дедлайна | Не применимо: в use case нет брони и окна отмены | Перейти к UC-004 только после создания брони |

### Постусловия

- Создана действующая сессия клиента.
- Персональные действия будут доступны после перехода в расписание.

### Трассируемость

BR-001, BR-012; FR-001; NFR-004; US-001.

## 5. UC-002 — Просмотр расписания и деталей слота

### Предусловия

- Клиент авторизован или приложение может показать кэшированные данные с пометкой неактуальности.
- Client API доступен для получения свежих данных либо приложение имеет кэш расписания.

### Основной успешный поток

1. Клиент открывает расписание.
2. Приложение устанавливает период ближайших 7 дней.
3. Приложение вызывает `API-SLOT-001` для получения слотов.
4. Приложение отображает дату, время, формат, инструктора и свободные места.
5. Клиент применяет фильтры по дате, формату и инструктору.
6. Приложение обновляет список по выбранным фильтрам.
7. Клиент открывает карточку слота.
8. Приложение вызывает `API-SLOT-002` и показывает время, инструктора, формат, свободные места и адрес.

### Альтернативные потоки

- **ALT-002-A:** клиент меняет период на другую доступную дату.
- **ALT-002-B:** клиент открывает кэш при отсутствии сети и видит пометку «Данные могут быть неактуальны».
- **ALT-002-C:** в выбранном периоде нет треннировок; приложение показывает Empty State и предлагает изменить фильтр.
- **ALT-002-D:** клиент закрывает карточку и возвращается к расписанию без изменения данных.

### Потоки исключений

| ID | Событие | Реакция приложения | Восстановление |
|---|---|---|---|
| EXC-002-01 | Ошибка SMS или истёкшая сессия | Остановить запрос и вернуть клиента на вход | Повторить UC-001 |
| EXC-002-02 | 0 свободных мест при race condition | Не показывать бронь как подтверждённую, обновить остаток | Вернуться к списку или выбрать другой слот |
| EXC-002-03 | Отмена после дедлайна | Не применимо: use case только читает слот | Отмена обрабатывается в UC-004 |
| EXC-002-04 | Ошибка API или отсутствие сети без кэша | Показать состояние ошибки, не выдавать пустой список за отсутствие треннировок | Повторить загрузку |

### Постусловия

- Клиент видит актуальный или явно устаревший список.
- Выбранный слот доступен для перехода к бронированию, если он не отменён и не заполнен.

### Трассируемость

BR-001, BR-002, BR-003, BR-014; FR-002, FR-003; NFR-001, NFR-005, NFR-006, NFR-007; US-002, US-003.

## 6. UC-003 — Бронирование слота с выбором проката

### Предусловия

- Клиент авторизован.
- Слот доступен и открыт в карточке.
- Client API возвращает свободные места и варианты проката.

### Основной успешный поток

1. Клиент нажимает «Записаться».
2. Приложение создаёт форму для одного клиента без выбора количества людей.
3. Клиент выбирает для скальников и системы один из вариантов: своё или прокат.
4. Приложение показывает тариф и остаток проката.
5. Клиент подтверждает форму.
6. Приложение вызывает `API-BOOKING-001` с идентификатором слота, клиентом и комплектом снаряжения.
7. Существующий бэкенд атомарно проверяет место.
8. Client API возвращает подтверждение одной брони.
9. Приложение показывает статус «Подтверждена», данные слота и «Оплата на месте».
10. Бронь появляется в разделе «Мои записи».

### Альтернативные потоки

- **ALT-003-A:** клиент выбирает своё снаряжение для обоих компонентов и не использует прокат.
- **ALT-003-B:** клиент выбирает только прокат скальников или только прокат системы.
- **ALT-003-C:** клиент возвращается назад и редактирует выбор снаряжения до отправки.
- **ALT-003-D:** прокат недоступен; клиент выбирает доступную альтернативу.

### Потоки исключений

| ID | Событие | Реакция приложения | Восстановление |
|---|---|---|---|
| EXC-003-01 | Ошибка SMS или истёкшая сессия | Не отправлять бронь, вернуть на вход | Повторить UC-001 и открыть слот |
| EXC-003-02 | 0 свободных мест при race condition, HTTP 409 | Не создавать локальную подтверждённую бронь, показать конфликт | Обновить слот и выбрать другой |
| EXC-003-03 | Отмена после дедлайна | Не применимо: бронь ещё не создана; окно отмены проверяется в UC-004 | Вернуться к форме другого слота |
| EXC-003-04 | Провал API после отправки | Не показывать успех; сверить статус существующей брони перед повтором | Повторить только после проверки |

### Постусловия

- Создана ровно одна бронь для одного клиента, либо действие завершено без брони.
- Способ оплаты зафиксирован как «Оплата на месте».
- Платёжная транзакция не создаётся.

### Трассируемость

BR-004, BR-005, BR-006, BR-011, BR-013, BR-014; FR-004, FR-005, FR-006; NFR-002, NFR-003; US-004.

## 7. UC-004 — Отмена брони клиентом

### Предусловия

- Клиент авторизован.
- У клиента есть подтверждённая активная бронь.
- Текущее время получено из источника истины.

### Основной успешный поток

1. Клиент открывает «Мои записи» и выбирает активную бронь.
2. Приложение вычисляет дедлайн: начало слота минус 2 часа.
3. До старта осталось не менее 2 часов.
4. Клиент нажимает «Отменить».
5. Приложение показывает подтверждение с датой и временем.
6. Клиент подтверждает действие.
7. Приложение вызывает `API-BOOKING-002`.
8. Client API возвращает статус «Отменена клиентом».
9. Приложение обновляет «Мои записи» и карточку брони.

### Альтернативные потоки

- **ALT-004-A:** клиент закрывает подтверждение и возвращается к записи без изменений.
- **ALT-004-B:** бронь уже отменена клиентом или скалодромом; приложение показывает текущий статус.
- **ALT-004-C:** клиент возвращается в расписание и выбирает другой доступный слот.

### Потоки исключений

| ID | Событие | Реакция приложения | Восстановление |
|---|---|---|---|
| EXC-004-01 | Ошибка SMS или истёкшая сессия | Не менять статус до авторизации | Повторить UC-001 и открыть бронь |
| EXC-004-02 | 0 свободных мест при race condition | Не применимо: отменяется существующая бронь, а не создаётся новая | Обновить список и продолжить с UC-004 |
| EXC-004-03 | Отмена после дедлайна | Заблокировать действие, объяснить остаток менее 2 часов, не отправлять API-запрос | Выбрать другой слот или дождаться внешней обработки |
| EXC-004-04 | Ошибка API | Сохранить исходный статус, показать возможность повторить | Повторить только при актуальном статусе |

### Постусловия

- При успешной отмене бронь имеет статус «Отменена клиентом».
- При отмене после дедлайна исходная бронь остаётся активной.

### Трассируемость

BR-007, BR-013; FR-007, FR-008; NFR-003; US-005, US-006.

## 8. UC-005 — Обработка отмены тренировки скалодромом

### Предусловия

- У клиента есть подтверждённая бронь на слот.
- Существующая инфраструктура изменила статус слота.
- Client API возвращает статус «Отменена скалодромом» и причину.

### Основной успешный поток

1. Существующий бэкенд отменяет слот из-за профилактики или проверки снаряжения.
2. Backend отправляет событие через согласованный канал.
3. Приложение получает push и открывает детали связанной брони.
4. Приложение обновляет запись через Client API.
5. Приложение показывает статус «Отменена скалодромом» и причину.
6. Приложение оставляет бронь в истории «Мои записи».
7. Приложение блокирует повторную запись в отменённый слот.

### Альтернативные потоки

- **ALT-005-A:** push не доставлен, но клиент открывает «Мои записи»; приложение получает актуальный статус через API.
- **ALT-005-B:** клиент отказался от push; уведомление не блокирует получение статуса при открытии приложения.
- **ALT-005-C:** клиент повторно открывает детали; статус и причина остаются без изменений.

### Потоки исключений

| ID | Событие | Реакция приложения | Восстановление |
|---|---|---|---|
| EXC-005-01 | Ошибка SMS или истёкшая сессия | Не удалять бронь; запросить повторный вход и затем обновить статус | Повторить UC-001 |
| EXC-005-02 | 0 свободных мест при race condition | Не применимо: слот уже отменён внешней системой | Показать статус «Отменена скалодромом» |
| EXC-005-03 | Отмена после дедлайна | Не применимо: отмена инициирована скалодромом, а не клиентом; ограничение 2 часов не применяется | Сохранить бронь в специальном статусе |
| EXC-005-04 | Push или API недоступны | Показать сохранённые данные с меткой актуальности и предложить обновить | Повторить при подключении |

### Постусловия

- Бронь не удалена.
- Причина и статус отображаются клиенту.
- Повторная запись в отменённый слот заблокирована.

### Трассируемость

BR-008, BR-010, BR-013; FR-009, FR-011; NFR-003, NFR-005; US-007.

## 9. UC-006 — Оценка инструктора после занятия

### Предусловия

- Бронь имеет статус «Завершена».
- Клиент авторизован как участник этой брони.
- Оценка ещё не была сохранена.

### Основной успешный поток

1. Клиент открывает «Мои записи».
2. Клиент выбирает завершённую запись.
3. Приложение показывает действие оценки инструктора.
4. Клиент выбирает от 1 до 5 звёзд.
5. Приложение вызывает `API-RATING-001`.
6. Client API сохраняет оценку и возвращает статус «Оценена».
7. Приложение обновляет запись и показывает выбранное значение.

### Альтернативные потоки

- **ALT-006-A:** клиент не оставляет оценку и возвращается к списку.
- **ALT-006-B:** клиент уже оценил инструктора; приложение показывает сохранённую оценку и не разрешает повторную отправку.
- **ALT-006-C:** инструктор или название тренировки отсутствует в ответе; приложение не позволяет отправить некорректную оценку.

### Потоки исключений

| ID | Событие | Реакция приложения | Восстановление |
|---|---|---|---|
| EXC-006-01 | Ошибка SMS или истёкшая сессия | Не отправлять оценку до авторизации | Повторить UC-001 |
| EXC-006-02 | 0 свободных мест при race condition | Не применимо: оценка не меняет количество мест | Вернуться к деталям завершённой записи |
| EXC-006-03 | Отмена после дедлайна | Не применимо: оценка доступна только для завершённой, не отменённой записи | Выбрать другую завершённую запись |
| EXC-006-04 | Бронь ещё не завершена | Не показывать или заблокировать действие оценки | Дождаться статуса «Завершена» |
| EXC-006-05 | Повторная отправка оценки | Не создавать вторую оценку, показать текущую | Обновить детали |

### Постусловия

- При успешной отправке сохранена одна оценка от 1 до 5.
- При нарушении условий статус брони не изменяется.

### Трассируемость

BR-009; FR-010; NFR-006; US-008.
