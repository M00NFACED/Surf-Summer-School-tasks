# 06 — Ограничения и границы скоупа MVP

| Поле | Значение |
|---|---|

## 2. Скоуп

В текущую поставку входят:

- мобильное приложение Клиента;
- Client API как клиентский контракт;
- авторизация Клиента по номеру телефона и SMS-коду;
- чтение расписания и деталей слота;
- фильтрация по дате, формату и инструктору;
- бронирование одного клиента с выбором снаряжения;
- раздел «Мои записи»;
- клиентская отмена с проверкой окна 2 часа;
- отображение отмены слота скалодромом, статуса, причины и push-события;
- оценка инструктора после завершения тренировки;
- состояния загрузки, пустого результата, ошибки, офлайн-кэша и конкурентного отказа;
- фиксация способа оплаты «на месте» без онлайн-платежа.

Границы соответствуют `01-business-requirements.md`, `02-functional-requirements.md` и `05-use-cases.md` по смыслу use cases.

## 3. Вне скоупа

Следующие функции и системы не создаются и не изменяются в рамках MVP:

- админка владельца или администратора;
- мобильное приложение и интерфейс инструктора;
- веб-интерфейс любой административной роли;
- внутренняя база данных, транзакции, триггеры и миграции существующего бэкенда;
- генерация, публикация и редактирование расписания;
- управление инструкторами, зонами и прокатным фондом в приложении;
- онлайн-оплата, платёжный шлюз, карты, чеки, возвраты и фискальная отчётность;
- автоматический перенос клиента на другой слот при отмене скалодромом;
- программа лояльности и выдача постоянным клиентам специальных условий;
- комментарии, фотографии и публичный рейтинг клиентов.

## 4. Ограничения

| ID | Ограничение | Следствие для MVP | Связи |
|---|---|---|---|
| CON-001 | Только роль Клиента | Нет экранов и команд Администратора или Инструктора | BR-012 |
| CON-002 | Существующий бэкенд — black-box источник истины | Приложение доверяет ответам Client API и не реализует серверную транзакционность | BR-013 |
| CON-003 | Client API — единственная граница интеграции | Слоты, форматы, зоны, инструкторы, тарифы и адрес берутся из контракта | BR-002, BR-014 |
| CON-004 | Бронь на одного человека | В форме нет группового количества участников | BR-005, FR-004 |
| CON-005 | Окно отмены — не позднее 2 часов | После дедлайна клиентская отмена блокируется | BR-007, FR-008 |
| CON-006 | Оплата на месте | В приложении нет платёжного шага и платёжного токена | BR-011, FR-006 |
| CON-007 | Мобильный клиент от 360 dp | Карточки и действия проектируются без обязательной горизонтальной прокрутки | NFR-006 |
| CON-008 | При отсутствии сети бронь не создаётся | Кэш расписания доступен только для чтения | NFR-005 |
| CON-009 | Оценка только после завершения | Для активных и отменённых записей действие оценки заблокировано | BR-009, FR-010 |

## 5. Допущения

| ID | Допущение | Влияние | Способ подтверждения |
|---|---|---|---|
| ASM-001 | Существующий бэкенд атомарно проверяет свободное место | Приложение может показать остаток, но только API подтверждает бронь | Интеграционный race-тест |
| ASM-002 | Backend возвращает 409 Conflict при отсутствии места | Приложение может безопасно обработать конкурентный отказ | Проверка контракта и тест API |
| ASM-003 | Client API возвращает тариф, наличие проката, адрес, формат, зону, инструктора и статусы | Приложение не дополняет данные из легаси-источников | Проверка схемы ответа |
| ASM-004 | Время старта и дедлайн отмены приходят с серверной временной меткой | Клиентские часы не влияют на допустимость отмены | Проверка часового пояса и boundary case |
| ASM-005 | SMS- и Push-сервисы доступны через согласованные внешние контракты | Ошибка внешнего сервиса не должна подтверждать ложное действие | Проверка error-сценариев |
| ASM-006 | Оплата принимается вне приложения на месте скалодрома | В MVP нет финансовой транзакции и чека | Подтверждение сценария на месте |
| ASM-007 | Расписание по умолчанию горизонтом 7 дней и может быть пустым | Приложение показывает Empty State, а не создаёт фиктивные слоты | Проверка пустого ответа API |

## 6. Зависимости

- Существующий бэкенд предоставляет данные расписания и выполняет атомарную проверку мест.
- Client API предоставляет клиентский контракт и коды ошибок, включая HTTP 409.
- SMS-провайдер подтверждает номер телефона по SMS-коду.
- Push-провайдер доставляет уведомление об отмене скалодромом.
- Владелец скалодрома принимает оплату на месте вне приложения.

## 7. Критерии выхода за границу

Функция считается вне MVP, если она требует изменения существующего бэкенда, роли Администратора или Инструктора, веб-интерфейса, онлайн-платежа, управления расписанием или исторических данных. Такое изменение оформляется отдельным BR и не выполняется в текущем коммите.
