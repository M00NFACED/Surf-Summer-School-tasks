## 3. Истории

### US-001 — Вход по номеру телефона

**Как Клиент, я хочу войти по номеру телефона и коду из SMS, чтобы записываться на тренировки без отдельного пароля.**

**Связи:** BR-001, BR-012; FR-001; UC-001; NFR-004.

#### INVEST

| Критерий | Проверка |
|---|---|
| Independent | История начинается с отдельного состояния неавторизованного клиента и не требует готовой записи. |
| Negotiable | Способ хранения сессии и текст ошибок можно обсуждать без изменения ценности. |
| Valuable | Даёт клиенту доступ к расписанию и личным действиям. |
| Estimable | Содержит одно действие входа и два независимых критерия проверки. |
| Small | Ограничена аутентификацией; расписание и бронирование вынесены в другие истории. |
| Testable | Проверяется по коду, формату телефона и результату сессии. |

#### Критерии приёмки

- **US-001-AC-01:** Given клиент не авторизован и вводит `+7XXXXXXXXXX`, When он запрашивает код, Then приложение отправляет запрос через Client API и показывает поле ввода кода.
- **US-001-AC-02:** Given получен одноразовый код, When код введён верно, Then создаётся клиентская сессия и открывается расписание.
- **US-001-AC-03:** Given код неверный или истёк, When клиент отправляет его, Then сессия не создаётся и отображается понятная ошибка с возможностью запросить новый код.

### US-002 — Поиск тренировки

**Как Клиент, я хочу увидеть ближайшие доступные тренировки и отфильтровать их по дате, формату и инструктору, чтобы быстро выбрать подходящий слот.**

**Связи:** BR-001, BR-002, BR-003, BR-014; FR-002; UC-002; NFR-001, NFR-005, NFR-007.

#### INVEST

| Критерий | Проверка |
|---|---|
| Independent | История начинается после открытия приложения и не зависит от наличия созданной брони. |
| Negotiable | Визуальный вид фильтров и порядок группировки можно менять. |
| Valuable | Снижает время поиска и исключает неподходящие форматы и инструкторов. |
| Estimable | Содержит один read-use case и три независимых фильтра. |
| Small | Ограничена списком и фильтрацией; детали вынесены в US-003. |
| Testable | Проверяется наборами данных, границами периода и пустым ответом. |

#### Критерии приёмки

- **US-002-AC-01:** Given клиент открывает расписание, When API возвращает слоты, Then по умолчанию отображается период ближайших 7 дней.
- **US-002-AC-02:** Given доступны несколько дат, форматов и инструкторов, When клиент применяет фильтры, Then список содержит только слоты, удовлетворяющие всем выбранным фильтрам.
- **US-002-AC-03:** Given API возвращает 0 слотов за 7 дней, When клиент открывает расписание, Then отображается сообщение «Пока нет доступных тренировок» и возможность изменить период.

### US-003 — Просмотр деталей слота

**Как Клиент, я хочу посмотреть полную карточку выбранной тренировки, чтобы решить, подходит ли мне время, формат, инструктор и адрес.**

**Связи:** BR-002, BR-014; FR-003; UC-002; NFR-006.

#### INVEST

| Критерий | Проверка |
|---|---|
| Independent | История не требует предварительного бронирования. |
| Negotiable | Компоновка карточки и порядок полей могут быть изменены. |
| Valuable | Снижает риск записаться не на ту тренировку или зал. |
| Estimable | Один read-use case с фиксированным набором полей. |
| Small | Содержит только детали и переход к бронированию. |
| Testable | Сравнивает обязательные поля с ответом API и поведение при отсутствии данных. |

#### Критерии приёмки

- **US-003-AC-01:** Given слот доступен, When клиент открывает карточку, Then видны время, инструктор, формат, свободные места и адрес зала.
- **US-003-AC-02:** Given на слоте доступен прокат, When открыта карточка, Then видны тариф и наличие каждого варианта снаряжения.
- **US-003-AC-03:** Given свободных мест нет, When открыта карточка, Then кнопка бронирования недоступна и причина отображается явно.

### US-004 — Оформление брони

**Как Клиент, я хочу записаться на тренировку за одного человека, выбрать своё снаряжение или прокат и увидеть, что оплата будет на месте, чтобы быстро подтвердить участие.**

**Связи:** BR-004, BR-005, BR-006, BR-011, BR-013, BR-014; FR-004, FR-005, FR-006; UC-003; NFR-002, NFR-003.

#### INVEST

| Критерий | Проверка |
|---|---|
| Independent | История начинается с доступного слота; данные подготовлены предыдущими историями. |
| Negotiable | Порядок полей и визуальная форма подтверждения обсуждаются отдельно. |
| Valuable | Заменяет ручную запись и фиксирует необходимое снаряжение. |
| Estimable | Содержит одну команду создания брони и обработку её ответа. |
| Small | Не включает изменение расписания и онлайн-оплату. |
| Testable | Проверяется на одном клиенте, выборе снаряжения, успешном ответе и 409. |

#### Критерии приёмки

- **US-004-AC-01:** Given доступный слот, When клиент подтверждает форму, Then отправляется запрос ровно на одного клиента с выбранными источниками скальников и системы.
- **US-004-AC-02:** Given API подтверждает бронь, When клиент получает ответ, Then создаётся одна запись со статусом «Подтверждена» и текстом «Оплата на месте».
- **US-004-AC-03:** Given другой клиент занял последнее место, When API возвращает HTTP 409 Conflict, Then приложение не создаёт подтверждённую или фантомную бронь и предлагает обновить слот.

### US-005 — Просмотр моих записей

**Как Клиент, я хочу видеть активные и прошедшие брони в одном разделе, чтобы понимать своё расписание и историю посещений.**

**Связи:** BR-001, BR-005, BR-008, BR-009; FR-007; UC-004, UC-005, UC-006; NFR-005, NFR-006.

#### INVEST

| Критерий | Проверка |
|---|---|
| Independent | История требует авторизации, но не требует отдельного нового слота. |
| Negotiable | Способ группировки и сортировки можно обсуждать. |
| Valuable | Даёт единый источник статуса и переходов к отмене или оценке. |
| Estimable | Один список с двумя категориями и одним набором деталей. |
| Small | Не включает редактирование расписания или историю всех клиентов. |
| Testable | Проверяется на данных с активными, прошедшими и отменёнными статусами. |

#### Критерии приёмки

- **US-005-AC-01:** Given у клиента есть записи, When открывается «Мои записи», Then записи разделены на активные и прошедшие.
- **US-005-AC-02:** Given запись отменена скалодромом, When клиент открывает детали, Then сохранены статус «Отменена скалодромом» и причина.
- **US-005-AC-03:** Given запись завершена и ещё не оценена, When открывается деталь, Then доступно действие оценки инструктора.

### US-006 — Отмена записи

**Как Клиент, я хочу отменить бронь не позднее чем за два часа до начала, чтобы освободить место без нарушения правил скалодрома.**

**Связи:** BR-007, BR-013; FR-008; UC-004; NFR-003.

#### INVEST

| Критерий | Проверка |
|---|---|
| Independent | Требует существующей активной брони, но не зависит от других действий. |
| Negotiable | Текст подтверждения и способ расчёта дедлайна можно обсуждать. |
| Valuable | Позволяет освободить место и сохранить прозрачность правил. |
| Estimable | Содержит одно действие и проверку одного временного порога. |
| Small | Не изменяет слот и не создаёт новую тренировку. |
| Testable | Проверяется на времени до и после дедлайна. |

#### Критерии приёмки

- **US-006-AC-01:** Given до начала не менее 2 часов, When клиент подтверждает отмену, Then API принимает команду и запись получает статус «Отменена клиентом».
- **US-006-AC-02:** Given до начала менее 2 часов, When клиент открывает бронь, Then кнопка отмены заблокирована и объяснено ограничение.
- **US-006-AC-03:** Given отмена уже выполнена, When клиент повторно открывает запись, Then приложение не отправляет повторную команду и показывает текущий статус.

### US-007 — Получение отмены скалодромом

**Как Клиент, я хочу получить push и увидеть причину отмены тренировки со статусом «Отменена скалодромом», чтобы понимать, что произошло с моей записью.**

**Связи:** BR-008, BR-010, BR-013; FR-009, FR-011; UC-005; NFR-003, NFR-005.

#### INVEST

| Критерий | Проверка |
|---|---|
| Independent | Сценарий инициируется внешним событием и не требует ручного редактирования расписания. |
| Negotiable | Текст уведомления и момент запроса разрешения обсуждаются. |
| Valuable | Предотвращает неявку и сохраняет доверие к записи. |
| Estimable | Один push-событие, один статус и одно правило запрета повторной записи. |
| Small | Не включает интерфейс организатора и процедуру переноса. |
| Testable | Проверяется push, обновлением API, статусом и причиной. |

#### Критерии приёмки

- **US-007-AC-01:** Given скалодром отменил слот, When приложение получает событие или открывает «Мои записи», Then бронь имеет статус «Отменена скалодромом» и причину.
- **US-007-AC-02:** Given клиент разрешил push, When приходит событие отмены, Then отображается уведомление со ссылкой на бронь.
- **US-007-AC-03:** Given слот отменён скалодромом, When клиент пытается повторно записаться, Then действие запрещено независимо от свободного времени в прошлом.

### US-008 — Оценка инструктора

**Как Клиент, я хочу оставить оценку инструктору от 1 до 5 звёзд только после завершения тренировки, чтобы дать скалодрому понятную обратную связь.**

**Связи:** BR-009; FR-010; UC-006; NFR-006.

#### INVEST

| Критерий | Проверка |
|---|---|
| Independent | Требует только завершённой брони и не требует отдельного отчёта. |
| Negotiable | Визуальный вид звёзд и возможность пропустить оценку обсуждаются. |
| Valuable | Помогает владельцу видеть качество работы инструкторов. |
| Estimable | Одна форма оценки, пять допустимых значений и один вызов API. |
| Small | Не включает комментарии, фото и рейтинг других клиентов. |
| Testable | Проверяется статусом брони, диапазоном значения и повторной отправкой. |

#### Критерии приёмки

- **US-008-AC-01:** Given запись имеет статус «Завершена» и не оценена, When клиент открывает детали, Then доступны пять звёзд.
- **US-008-AC-02:** Given клиент выбирает значение от 1 до 5, When он отправляет оценку, Then API сохраняет оценку и запись получает статус «Оценена».
- **US-008-AC-03:** Given запись активна, отменена или уже оценена, When клиент пытается оценить инструктора, Then действие недоступно или отклоняется без изменения записи.
