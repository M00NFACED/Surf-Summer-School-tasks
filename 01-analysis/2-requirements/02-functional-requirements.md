## 3. Детализированные требования

### FR-001 — Авторизация по номеру телефона и коду из SMS

**Назначение:** идентифицировать Клиента перед доступом к персональным действиям.

**Предусловие:** приложение запущено; клиент ещё не имеет активной сессии.

**Поведение:**

1. Экран входа принимает телефон в формате E.164 `+7XXXXXXXXXX`.
2. После валидации телефона приложение запрашивает через Client API отправку SMS-кода.
3. Клиент вводит полученный код.
4. При успешной проверке API создаёт клиентскую сессию и открывает доступ к расписанию и «Моим записям».
5. Неверный, истёкший или уже использованный код не создаёт сессию; клиент может запросить новый код.
6. Приложение не запрашивает пароль и не реализует административный вход.

**Ошибки и состояния:** нет сети, код не пришёл, код неверный, срок действия кода истёк, повторная отправка.

**Связи:** BR-001, BR-012; UC-001; US-001; NFR-004.

### FR-002 — Расписание слотов и фильтрация

**Назначение:** показать клиенту доступные тренировки.

**Поведение:**

1. При первом открытии экран запрашивает слоты на ближайшие 7 дней от текущего момента.
2. Для каждого слота отображаются дата, время, формат, инструктор и доступность.
3. Пользователь может изменить период фильтрацией по дате.
4. Пользователь может фильтровать по формату: «Новичковый болдеринг» или «Трассы с верёвкой».
5. Пользователь может фильтровать по инструктору.
6. Фильтры применяются к данным, полученным через Client API; расписание не создаётся и не редактируется в приложении.
7. Если в выбранном периоде нет тренировок, показывается Empty State с сообщением «Пока нет доступных тренировок».

**Ошибки и состояния:** загрузка, отсутствие сети, кэш с пометкой неактуальности, пустой результат, ошибка API.

**Связи:** BR-001, BR-002, BR-003, BR-014; UC-002; US-002; NFR-001, NFR-005, NFR-007.

### FR-003 — Детальная карточка слота

**Назначение:** дать клиенту всю информацию для решения о бронировании.

**Поведение:**

1. По выбранному слоту открывается карточка с временем начала и окончания.
2. Карточка показывает формат, инструктора, свободные места и адрес зала.
3. Карточка показывает доступные варианты проката и тариф, если они нужны для выбора.
4. Если мест нет, кнопка бронирования не активна и отображается причина недоступности.
5. Карточка не предлагает редактирование расписания или данных инструктора.

**Связи:** BR-002, BR-014; UC-002; US-003; NFR-006.

### FR-004 — Бронирование на одного человека

**Назначение:** создать одну запись без группового переполнения.

**Поведение:**

1. Форма бронирования всегда создаёт запись для одного клиента; выбор количества людей отсутствует.
2. Перед отправкой отображаются выбранные слот, инструктор, формат и адрес.
3. Приложение отправляет идентификатор слота и данные одного клиента в Client API.
4. Только успешный ответ API переводит форму в состояние подтверждённой брони.
5. При HTTP 409 Conflict или отсутствии свободного места бронь не создаётся, приложение сообщает о конфликте и может предложить обновить детали.
6. Приложение не использует локальный счётчик мест как доказательство наличия места.

**Связи:** BR-004, BR-005, BR-013; UC-003; US-004; NFR-002, NFR-003.

### FR-005 — Выбор снаряжения

**Назначение:** зафиксировать оснащение клиента или потребность в прокате.

**Поведение:**

1. Для скальников клиент выбирает `своё` или `прокат скальников`.
2. Для страховочной системы клиент выбирает `своё` или `прокат системы`.
3. Для проката отображаются наличие и тариф из Client API.
4. Если выбранный прокат недоступен, приложение не позволяет продолжить и предлагает выбрать доступную альтернативу.
5. В запрос бронирования включаются выбранные варианты снаряжения.

**Связи:** BR-006, BR-014; UC-003; US-004; NFR-003.

### FR-006 — Создание брони и оплата на месте

**Назначение:** подтвердить запись и явно зафиксировать способ оплаты.

**Поведение:**

1. После проверки доступности клиент подтверждает бронь.
2. Приложение отправляет данные слота, одного клиента и выбранного снаряжения в Client API.
3. При успешном ответе показываются идентификатор или время тренировки, статус подтверждения и текст «Оплата на месте».
4. Приложение не создаёт платёжную транзакцию, не принимает карту и не рассчитывает онлайн-возврат.
5. Если запрос не дал однозначного ответа, приложение сначала запрашивает актуальный статус существующей брони и не отправляет дубликат без проверки.

**Связи:** BR-006, BR-011, BR-013; UC-003; US-004; NFR-002, NFR-003.

### FR-007 — Раздел «Мои записи»

**Назначение:** показать клиенту историю и текущие записи.

**Поведение:**

1. Раздел «Мои записи» разделяет записи на активные и прошедшие.
2. Для каждой записи отображаются слот, инструктор, формат, статус, выбранное снаряжение и способ оплаты.
3. Для активной записи доступны детали и разрешённые действия.
4. Для прошедшей записи доступна оценка, если запись завершена и ещё не оценена.
5. При открытии раздела приложение обновляет статусы из Client API.
6. Отменённые скалодромом записи остаются в истории с отдельным статусом.

**Связи:** BR-001, BR-005, BR-008, BR-009; UC-004, UC-005, UC-006; US-005; NFR-005, NFR-006.

### FR-008 — Клиентская отмена брони

**Назначение:** освободить место до начала тренировки при соблюдении временного окна.

**Поведение:**

1. В деталях активной брони приложение вычисляет дедлайн отмены по серверному времени старта: за 2 часа.
2. Если до старта не менее 2 часов, кнопка отмены активна.
3. Перед отправкой отмены приложение показывает подтверждение с датой и временем тренировки.
4. При успешном ответе статус меняется на «Отменена клиентом».
5. Если до старта менее 2 часов, приложение блокирует кнопку, объясняет ограничение и не отправляет запрос отмены.

**Связи:** BR-007, BR-013; UC-004; US-006; NFR-003.

### FR-009 — Отмена слота скалодромом

**Назначение:** корректно отразить внешнее изменение расписания и сохранить историю брони.

**Поведение:**

1. Существующий бэкенд сообщает через Client API статус «Отменена скалодромом» и причину.
2. Приложение обновляет запись в «Моих записях» и карточке слота.
3. Причина отображается рядом со статусом; допустимые причины включают профилактику или проверку снаряжения.
4. Приложение запрещает повторную запись в этот отменённый слот.
5. Приложение не удаляет бронь и не выдаёт отмену скалодрома за клиентскую.

**Связи:** BR-008, BR-013; UC-005; US-007; NFR-003, NFR-005.

### FR-010 — Оценка инструктора

**Назначение:** получить обратную связь после фактически завершённой тренировки.

**Поведение:**

1. Действие оценки доступно только для записи в статусе «Завершена».
2. Для завершённой записи клиент выбирает целое значение от 1 до 5 звёзд.
3. Приложение отправляет оценку один раз для конкретной брони.
4. После сохранения запись получает статус «Оценена», а повторная отправка блокируется.
5. Для активной, отменённой или ещё не завершённой записи действие оценки недоступно.

**Связи:** BR-009; UC-006; US-008; NFR-006.

### FR-011 — Регистрация и обработка push

**Назначение:** доставить клиенту значимое изменение и открыть связанную запись.

**Поведение:**

1. При необходимости приложение запрашивает разрешение пользователя на уведомления.
2. После разрешения приложение регистрирует токен устройства через Client API или согласованный push-шлюз.
3. Push об отмене скалодромом содержит тип события, название слота и безопасный текст без лишних персональных данных.
4. Открытие push ведёт в детали затронутой брони.
5. Отказ от push не блокирует расписание, бронирование и получение статуса при следующем открытии приложения.

**Связи:** BR-008, BR-010; UC-005; US-007; NFR-005.

## 4. Общие правила поведения

- Все даты и время отображаются в часовом поясе зала; источник истины — данные Client API.
- Статусы броней и слотов нельзя назначать только локально без подтверждающего ответа API.
- Повторное нажатие на действие во время запроса блокируется.
- Для каждого сетевого действия предусмотрены состояния загрузки, ошибки и повторной попытки.
- Приложение показывает только функциональность роли Клиента.
