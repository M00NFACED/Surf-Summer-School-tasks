# SCR-003 — Расписание тренировок

## 1. Метаданные

| Поле | Значение |
|---|---|
| ID | `SCR-003` |
| Название | Расписание тренировок |
| Роль | Клиент |
| Тип | Список с фильтрами |
| Маршрут | `schedule` |
| Точка входа | Успешная авторизация, push без корректного deep link, нижняя навигация |
| Связанные требования | `BR-001`, `BR-002`, `BR-003`, `BR-014`, `FR-002`, `NFR-001`, `NFR-005`, `NFR-007`, `US-002`, `UC-002` |
| Версия | 1.0.0 |
| Приоритет | Must |

## 2. Цель и пользовательский сценарий

- Цель: показать доступные тренировки на ближайшие 7 дней и позволить отфильтровать их перед открытием карточки слота.
- Основной сценарий: после входа приложение запрашивает `GET /slots`, отображает список, пользователь меняет фильтры и выбирает слот.
- Условия доступа: действует Bearer-токен; сеть доступна либо в памяти есть кэш расписания.
- Результат: пользователь видит релевантные слоты, понимает актуальность данных и открывает `SCR-004`.

## 4. Состояния экрана

| Состояние | Условие | Отображение | Действие клиента |
|---|---|---|---|
| Initial | Экран открыт, данные ещё не загружены | Заголовок, фильтры, Skeleton 3–4 карточек | Дождаться данных или вернуться |
| Loading | Выполняется `GET /slots` или смена фильтра | Skeleton или сохранённый список с индикатором обновления | Дождаться; повторный запрос заблокирован |
| Success | API вернул HTTP 200 и `items` | Список актуальных слотов, счётчик и выбранные фильтры | Открыть карточку слота |
| Empty | API вернул 0 слотов за выбранный период | «Пока нет доступных тренировок», смена периода, сброс фильтров, Retry | Изменить условия или повторить |
| Error | API вернул 400, 401 или 503 | Сообщение об ошибке с Retry; при 401 — вход | Повторить или войти |
| Offline | Нет сети, но есть кэш | Кэш слотов с меткой «Данные могут быть неактуальны», кнопка обновления | Читать кэш, вернуться после подключения |
| Forbidden | Токен истёк или API вернул 401 | Клиентская зона закрывается, pending deep link без потери | Перейти на `SCR-001` и повторить вход |

## 5. Взаимодействие с API

| Вызов | Endpoint / метод | Назначение | Перед вызовом | Обработка ответа | Обработка ошибки |
|---|---|---|---|---|---|
| API-SLOT-001 | `GET /slots?from=&to=&format=&instructor_id=` | Получить отфильтрованное расписание | Bearer-токен; корректные ISO-даты и enum | `200 SlotListResponse`: нормализовать и отобразить `items` | `400`: исправить период/фильтр; `401`: вход; `503`: Retry |

Требования к обработке:

- При отсутствии `from/to` отправлять пустые query-параметры или позволить API применить дефолт 7 дней согласно контракту.
- Не смешивать сетевые данные с кэшем без Offline-метки.
- При 401 очистить или пометить сессию и вернуть на `SCR-001`.
- При 503 не заменять ошибку пустым расписанием; различать Error и Empty.
- При смене фильтра отменять предыдущий UI-request, чтобы поздний ответ не перетирал новый.
- Не отправлять запрос чаще, чем пользователь меняет фильтр; debounce не менее 300 мс.

## 6. Валидация и правила

- Период по умолчанию — ближайшие 7 дней от текущего момента.
- `format` допускает только `novice_bouldering` и `rope_routes`.
- `instructor_id` — UUID активного инструктора из API.
- `from` и `to` — валидные ISO 8601; `from` раньше `to`.
- Карточка показывает только поля, присутствующие в `TrainingSlotSummary`.
- Слот с `status = cancelled` не предлагает переход к бронированию.
- 0 свободных мест отображаются явно и не активируют CTA.
- Кэш маркируется как неактуальный; данные кэша не считаются источником истины.

## 7. Acceptance Criteria

### AC-SCR-003-001 — Расписание за 7 дней

**Связанные требования:** FR-002, NFR-001, NFR-007, BR-003

**Given** Клиент авторизован и открывает расписание впервые,
**When** API возвращает слоты,
**Then** приложение показывает период ближайших 7 дней и карточки с временем, форматом, инструктором и свободными местами.

### AC-SCR-003-002 — Фильтрация

**Связанные требования:** FR-002, BR-002, BR-014

**Given** на экране есть слоты с разными датами, форматами и инструкторами,
**When** Клиент применяет фильтры,
**Then** выполняется `GET /slots` с валидными параметрами и отображаются только слоты, соответствующие всем выбранным фильтрам.

### AC-SCR-003-003 — Empty State

**Связанные требования:** FR-002, NFR-007, BR-003

**Given** API возвращает 0 доступных тренировок на ближайшие 7 дней,
**When** Клиент открывает или фильтрует расписание,
**Then** отображается текст «Пока нет доступных тренировок», действия изменения периода/сброса фильтров и отсутствует CTA бронирования.

### AC-SCR-003-004 — Offline и ошибка

**Связанные требования:** FR-002, NFR-001, NFR-005, NFR-003

**Given** сеть недоступна или API вернул 503,
**When** Клиент открывает расписание,
**Then** приложение показывает кэш с меткой неактуальности либо Error с Retry и не выдаёт кэш за актуальные данные.
