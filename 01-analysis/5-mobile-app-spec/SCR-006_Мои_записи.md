# SCR-006 — Мои записи

## 1. Метаданные

| Поле | Значение |
|---|---|
| ID | `SCR-006` |
| Название | Мои записи |
| Роль | Клиент |
| Тип | Список персональных броней |
| Маршрут | `bookings/my` |
| Точка входа | Нижняя навигация, push без deep link, успешное бронирование |
| Связанные требования | `BR-001`, `BR-005`, `BR-008`, `BR-009`, `FR-007`, `NFR-005`, `NFR-006`, `US-005`, `UC-004`, `UC-005`, `UC-006` |
| Версия | 1.0.0 |
| Приоритет | Must |

## 2. Цель и пользовательский сценарий

- Цель: показать все брони текущего Клиента, разделив активные и прошедшие, и предоставить переход к деталям.
- Основной сценарий: Клиент открывает «Мои записи», видит две секции, выбирает бронь и переходит в `SCR-007`.
- Условия доступа: действует Bearer-токен; `GET /bookings/my` возвращает только брони текущего клиента.
- Результат: пользователь видит статусы, даты, инструкторов и доступные действия без записи чужих клиентов.

## 4. Состояния экрана

| Состояние | Условие | Отображение | Действие клиента |
|---|---|---|---|
| Initial | Экран открыт, список не загружен | Заголовок, пустые секции или Skeleton | Дождаться данных |
| Loading | Выполняется первичный запрос или Refresh | Skeleton карточек, кнопка Refresh disabled | Дождаться |
| Success | API вернул HTTP 200 | Активные и прошедшие секции с актуальными карточками | Открыть детали |
| Empty | `active` и/или `history` пусты | Сообщение для конкретной секции и переход к расписанию | Перейти к `SCR-003` |
| Error | API вернул 401 или 503 | Error с Retry; 401 направляет на вход | Повторить или войти |
| Offline | Нет сети и есть кэш списка | Последние записи с меткой неактуальности, refresh заблокирован | Прочитать кэш и обновиться позже |
| Forbidden | Сессия истекла или токен недействителен | Клиентская зона закрывается, данные не отображаются | Вернуться на `SCR-001` |

## 5. Взаимодействие с API

| Вызов | Endpoint / метод | Назначение | Перед вызовом | Обработка ответа | Обработка ошибки |
|---|---|---|---|---|---|
| API-BOOKING-003 | `GET /bookings/my` | Получить активные и прошедшие брони | Bearer-токен | `200 MyBookingsResponse`: распределить массивы по секциям и отрисовать статусы | `401`: вход; `503`: Retry; Offline: кэш с меткой |

Требования к обработке:

- Не запрашивать данные без Bearer-токена.
- Не объединять active/history в одну визуальную секцию; сохранять разделение ответа.
- Перед открытием карточки проверить, что `booking.id` принадлежит текущему списку.
- При 401 не показывать устаревшие персональные данные без метки и не продолжать клиентский сценарий.
- При push без корректного `booking_id` открыть список и не выбрать произвольную запись.
- При 503 различать ошибку и пустой ответ, не заменяя одно другим.

## 6. Валидация и правила

- Массивы `active` и `history` — массивы `Booking`; отсутствующий массив не заменять фиктивной записью.
- Статус отображается только из enum `BookingStatus`.
- Для `cancelled_by_venue` показывается `cancellation.reason`.
- Для `completed` без `rating` доступна оценка; для `rated` — просмотр сохранённого значения.
- Даты и время сортируются по `slot.starts_at`, а не по локальному тексту.
- При 0 свободных мест в старой карточке нельзя создать новую бронь без перехода на актуальный слот.
- Кэш не используется для изменения статуса, отмены или оценки.

## 7. Acceptance Criteria

### AC-SCR-006-001 — Разделение списка

**Связанные требования:** FR-007, BR-005, BR-008, BR-009, NFR-006

**Given** API возвращает активные и прошедшие брони,
**When** Клиент открывает «Мои записи»,
**Then** приложение показывает отдельные секции «Активные» и «Прошедшие», а каждая карточка содержит дату, время, формат, инструктора и текстовый статус.

### AC-SCR-006-002 — Статусы и пустые секции

**Связанные требования:** FR-007, FR-009, FR-010

**Given** есть отменённая скалодромом, завершённая или пустая секция,
**When** отображается список,
**Then** бейдж и причина корректны, CTA оценки доступен только завершённой неоценённой записи, а пустая секция имеет отдельное сообщение.

### AC-SCR-006-003 — Ошибка авторизации или сети

**Связанные требования:** FR-007, NFR-005

**Given** API возвращает 401/503 или сеть недоступна,
**When** Клиент обновляет список,
**Then** приложение не показывает чужие данные, предлагает вход или кэш с меткой и не создаёт локальный статус.
