# SCR-005 — Оформление брони

## 1. Метаданные

| Поле | Значение |
|---|---|
| ID | `SCR-005` |
| Название | Оформление брони и выбор проката снаряжения |
| Роль | Клиент |
| Тип | Форма бронирования |
| Маршрут | `bookings/new?slot_id={id}` |
| Точка входа | Доступный слот на `SCR-004` |
| Связанные требования | `BR-004`, `BR-005`, `BR-006`, `BR-011`, `BR-013`, `BR-014`, `FR-004`, `FR-005`, `FR-006`, `NFR-002`, `NFR-003`, `NFR-005`, `US-004`, `UC-003` |
| Версия | 1.0.0 |
| Приоритет | Must |

## 2. Цель и пользовательский сценарий

- Цель: оформить одну бронь для текущего Клиента, зафиксировать источник скальников и страховочной системы и показать оплату на месте.
- Основной сценарий: Клиент проверяет слот, выбирает `own` или `rental` для каждого компонента, подтверждает бронь и после HTTP 201 переходит в `SCR-007`.
- Условия доступа: действует Bearer-токен; `slot_id` существует, имеет статус `available` и положительное число свободных мест; есть актуальный ответ или безопасный контекст слота.
- Результат: создана ровно одна запись на одного человека; способ оплаты зафиксирован как `on_site`; локальная фантомная бронь не создаётся.

| CMP-005-04 | Выбор системы | Segmented control | Позволяет выбрать «Своё» или «Прокат системы» | Для rental обязателен `option_id` UUID и `available_quantity > 0` | `EquipmentOption.type = harness_system` | FR-005 |

Обязательные элементы:

- Краткая сводка тренировки и пояснение «одна бронь = один человек».
- Два обязательных селектора: скальники и страховочная система.
- Тариф и наличие проката из API.
- Явную плашку «Оплата на месте».
- Блокировку повторного submit и безопасную обработку HTTP 409.
- Loading, Empty для недоступного проката, Error, Offline и Forbidden.

## 4. Состояния экрана

| Состояние | Условие | Отображение | Действие клиента |
|---|---|---|---|
| Initial | Открыт слот, форма ещё не отправлена | Сводка, два выбора, payment badge, disabled CTA до выбора | Выбрать снаряжение |
| Loading | Идёт обновление деталей или `POST /bookings` | Skeleton/ spinner, controls read-only, CTA заблокирована | Дождаться терминального ответа |
| Success | API вернул HTTP 201 | Экран подтверждения с бронью, статусом и «Оплата на месте» | Перейти `SCR-007` |
| Empty | Для rental нет доступных позиций, но есть `own` | Информация «Прокат недоступен», доступен выбор «Своё» для компонента | Выбрать собственное снаряжение |
| Error | API вернул 400, 401, 409 или 503 | Сообщение по коду; 409 предлагает обновить слот; 401 — вход | Исправить, повторить или сменить слот |
| Offline | Нет сети | «Без подключения нельзя создать бронь», форма и CTA заблокированы | Восстановить сеть |
| Forbidden | Нет действующей сессии или слот недоступен | Отказ без раскрытия личных данных, pending slot сохраняется только до входа | Войти и повторить |

## 5. Взаимодействие с API

| Вызов | Endpoint / метод | Назначение | Перед вызовом | Обработка ответа | Обработка ошибки |
|---|---|---|---|---|---|
| API-BOOKING-001 | `POST /bookings` | Создать одну бронь и выбранные rental-опции | Bearer-токен; `slot_id`, `equipment.shoes`, `equipment.harness`, `payment_method = on_site` | `201 Booking`: показать подтверждение и перейти `SCR-007` | `400`: исправить выбор; `401`: войти; `409`: не создавать бронь, обновить слот; `503`: Retry без локального Pending |

Требования к обработке:

- Проверять наличие обоих equipment selections перед отправкой.
- Не включать `client_id` в тело; backend получает клиента из Bearer-токена.
- Не отправлять повторный POST во время активного запроса или после 201.
- При 409 удалить только локальный черновик, показать конфликт и обновить `GET /slots/{id}`.
- При неоднозначном ответе сначала получить `GET /bookings/my`, не создавая дубликат.
- При 503 и Offline не показывать `Подтверждена` до подтверждающего ответа.

## 6. Валидация и правила

- Бронь всегда на одного Клиента; селектора количества людей нет.
- Для скальников и системы обязательно выбрать один из `own` или `rental`.
- Rental-опция должна существовать, быть активна и иметь положительный `available_quantity`.
- `slot.status` должен быть `available`, `available_places > 0` на момент подтверждения.
- `payment_method` имеет единственное допустимое значение `on_site`.
- Онлайн-оплата, карта и платёжный токен не собираются.
- При 409 фантомная бронь и локальный `confirmed` не создаются.
- При 400 клиент может изменить только допустимые поля, не редактируя slot_id вручную.

## 7. Acceptance Criteria

### AC-SCR-005-001 — Успешное бронирование

**Связанные требования:** FR-004, FR-005, FR-006, NFR-002, BR-005, BR-011

**Given** доступный слот и выбраны `own` или доступный `rental` для скальников и системы,
**When** Клиент нажимает «Записаться»,
**Then** приложение отправляет `POST /bookings` с `payment_method = on_site`, а после HTTP 201 показывает одну подтверждённую бронь и плашку «Оплата на месте».

### AC-SCR-005-002 — Конкуренция за место

**Связанные требования:** FR-004, FR-006, NFR-003, BR-004, BR-013

**Given** перед отправкой последнее место занято другим Клиентом,
**When** API возвращает HTTP 409 Conflict,
**Then** приложение не создаёт подтверждённую или фантомную бронь, показывает конфликт и позволяет вернуться к обновлённой карточке слота.

### AC-SCR-005-003 — Ошибки и Offline

**Связанные требования:** FR-004, FR-005, FR-006, NFR-005

**Given** rental недоступен, API вернул 400/401/503 или нет сети,
**When** Клиент находится на форме,
**Then** приложение не отправляет некорректную бронь, сохраняет введённый выбор, блокирует submit без сети и предлагает безопасное восстановление.
