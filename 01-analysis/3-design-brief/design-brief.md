# Технический дизайн-бриф Surf

## 1. Метаданные

| Поле | Значение |
|---|---|
| Документ | `UI-BRIEF-001` |
| Назначение | Технический бриф для UI/UX-дизайнера мобильного приложения Клиента |
| Целевая платформа | Mobile-first, базовая ширина 360 dp |
| Источники | `01-analysis/2-requirements/`, `01-analysis/1-elicitation/domain-description.md` |
| Экраны | `SCR-001…SCR-008` |
| Статус | MVP baseline |

## 2. Дизайн-принципы

- Mobile-first: сначала проектируется один столбец для 360 dp, затем адаптивное расширение.
- Клиент быстро принимает решение: время, формат, инструктор, свободные места и адрес видны без дополнительного перехода.
- Статус всегда объяснён: действие, причина блокировки и следующий шаг не скрываются за иконкой.
- Данные из кэша никогда не выглядят как подтверждённые данные без пометки.
- Визуальная иерархия разделяет расписание, личные записи и системные состояния.

### 3.4. Поведение компонентов

- Основная кнопка занимает всю ширину контейнера на 360 dp.
- Вторичная кнопка и текстовая ссылка не конкурируют с основным действием на одном экране.
- Карточки слотов имеют одинаковый порядок полей: дата и время → формат → инструктор → места → CTA.
- Цвет статуса всегда дополнен текстовым label, а не используется как единственный сигнал.
- Все иконки имеют текстовую подпись или доступное имя.

## 4. Правила для экранов

### SCR-001 — Вход по номеру телефона

- Заголовок: «Войти в приложение».
- Поле телефона с маской `+7 (___) ___-__-__` и подсказкой формата E.164.
- Ошибка формата показывается под полем, кнопка не отправляет запрос.
- Показать согласие на обработку номера для получения SMS-кода, если это требуется внешним сервисом.

### SCR-002 — Ввод и проверка SMS-кода

- Заголовок: «Введите код из SMS».
- Показывать маску телефона без полного повторения персональных данных в push-like контексте.
- Поля кода имеют числовой ввод, таймер повторной отправки и состояние «Код неверен».
- При успешной проверке — переход в `SCR-003`; при ошибке — сохранить экран.

### SCR-003 — Расписание тренировок

- Верхний блок: период ближайших 7 дней и кнопка изменения даты.
- Фильтры: формат, инструктор и сброс фильтров.
- Карточка слота: время, формат, инструктор, свободные места, CTA.
- При кэше показывать плашку «Данные могут быть неактуальны».
- При отсутствии результатов показывать «Пока нет доступных тренировок».

### SCR-004 — Карточка слота

- Показывать время начала и окончания, формат, инструктора, адрес, свободные места.
- Вынести стоимость и наличие проката в блок «Снаряжение».
- При `0` мест заменить CTA на информационное состояние.
- Адрес должен быть доступен для копирования без сетевого вызова.

### SCR-005 — Оформление брони и выбор проката

- Сначала показать краткую сводку слота и клиента; количество людей не редактируется.
- Отдельными группами показать выбор скальников и страховочной системы: своё / прокат.
- Для проката показать наличие, тариф и состояние «недоступно».
- Перед CTA разместить плашку с текстом **«Оплата на месте»** и пояснением, что онлайн-списание отсутствует.
- Во время запроса блокировать повторное нажатие; при 409 не показывать подтверждение.

### SCR-006 — Мои записи

- Две секции: «Активные» и «Прошедшие».
- Карточка показывает дату, время, формат, инструктора, статус и CTA по статусу.
- Статус «Отменена скалодромом» сопровождается причиной.
- Завершённая неоценённая запись имеет CTA «Оценить инструктора».

### SCR-007 — Детали брони

- Показывать статус, дату и время, формат, инструктора, адрес, снаряжение и оплату.
- Для активной записи показывать кнопку «Отменить» только до дедлайна.
- Для отменённой скалодромом записи показывать статус и причину, а CTA бронирования — запретить.
- Push deep link открывает эту карточку после получения списка/актуальных данных.

### SCR-008 — Оценка инструктора

- Bottom Sheet поверх `SCR-007` с заголовком, именем инструктора и 1–5 звёздами.
- До выбора значения CTA не активна.
- После сохранения закрывать шторку и обновлять статус записи.
- Для неподходящего статуса не открывать шторку, а показать объяснение на `SCR-007`.

## 5. Состояния сетевых экранов

### Loading

- Скелетон повторяет структуру карточек, не показывает ложные данные.
- На экранах авторизации показывать прогресс только для конкретного запроса.
- Повторное действие блокируется до терминального ответа.

### Empty State

- Использовать на `SCR-003` при 0 тренировок за 7 дней.
- Текст: «Пока нет доступных тренировок».
- Действия: изменить дату, сбросить фильтры, повторить загрузку.
- Пустое состояние не должно содержать CTA бронирования.

### Error

- Различать сетевую ошибку, ошибку API и конфликт 409.
- Для 409 показать: «Место только что занято. Выберите другой слот».
- Для остальных ошибок: «Не удалось выполнить действие. Попробуйте ещё раз».
- Не показывать технический trace ID как основной пользовательский текст.

### Offline

- Расписание и ранее загруженные детали доступны из кэша с меткой неактуальности.
- Создание брони, отмена и отправка оценки блокируются до подключения.
- Не создавать локальный статус `Подтверждена` или `Pending` без ответа API.

## 6. Доступность

- Контраст текста и интерактивных элементов — не ниже WCAG AA.
- Все жесты имеют альтернативную кнопку.
- Порядок фокуса соответствует визуальному порядку.
- Статусы озвучиваются Screen Reader и не кодируются только цветом.
- Минимальная touch area — 48 × 48 dp, начиная с ширины 360 dp.
- Поддерживается масштаб текста без обрезания CTA и обязательных полей.
